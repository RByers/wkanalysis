4-Tier Availability Classification

Every entitlement across the WebKit repository is categorized into one of four availability tiers:

  • Private to Apple (114): com.apple.private.* and internal OS entitlements (com.apple.QuartzCore.*, com.apple.mediaremote.*, com.apple.tcc.*, com.apple.runningboard.*, com.apple.pac.*) that provisioning profiles only grant to Apple-signed system binaries.
  • BrowserEngineKit (6): Entitlements available to approved 3P alternative browser engines on iOS (com.apple.developer.web-browser-engine.{host,webcontent,rendering,networking,restrict.notifyd} and com.apple.developer.cs.allow-jit).
  • Restricted Other Way (20): Managed capabilities requiring separate Apple approval outside BrowserEngineKit (e.g., com.apple.developer.web-browser, com.apple.developer.WebKit.ServiceWorkers) or legacy/development App Sandbox exceptions.
  • Generally Available (19): Public developer entitlements available via standard Xcode capabilities (e.g., com.apple.developer.kernel.extended-virtual-addressing, com.apple.developer.hardened-process, keychain-access-groups).

Dual-Signing Architecture in WebKit

Why do static .entitlements files in Source/WebKit/UIProcess/AuxiliaryProcessExtensions/ look so minimal compared to production WebKit on iOS?

  • Template Plists (AuxiliaryProcessExtensions/*.entitlements): Only used when building standalone BrowserEngineKit extensions or simulator builds where WK_USE_RESTRICTED_ENTITLEMENTS == NO. They contain only the 6 BrowserEngineKit + public entitlements.
  • Production System Signing (Source/WebKit/Scripts/process-entitlements.sh): When building Apple’s system WebKit on iphoneos (WK_USE_RESTRICTED_ENTITLEMENTS == YES), ios_family_process_{webcontent,gpu,network,webpushd,adattributiond,model}_entitlements dynamically injects ~60 Apple-private entitlements into WebKit’s system helper processes.
