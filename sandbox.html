1. Purpose Categories (Why the change was made)

  • Security Hardening Proactively reducing attack surface: blocking Unix syscalls, Mach services, IOKit user-clients/properties, kernel MIG routines, or restricting rules to pre-launch / Lockdown Mode.
  • Feature Enablement Granting permissions required by new WebKit features, OS frameworks, or introducing new sandboxed processes (GPU, WebAuthn, Model, adattributiond, webpushd).
  • Bug Fix & Compat Fixing runtime sandbox violations, crashes, hangs, or regressions caused by iOS/visionOS SDK updates or overly tight prior blocks.
  • Telemetry & Logging Adding or removing with telemetry, with telemetry-backtrace, or with no-report to audit rule usage before blocking.
  • Refactor & Cleanup Extracting shared macros (*-defines.sb), removing dead rules/comments, or formatting without changing intended policy.
  • Revert Reverting a prior sandbox commit due to functional regressions, performance hits, or build breakage.

2. Sandbox Effect (How the policy changed)

  • ▼ Block More Net tightening of the sandbox: adds (deny ...) rules, removes (allow ...) rules, or gates existing permissions behind narrower conditions (e.g., sandbox-state-flags or Lockdown Mode).
  • ▲ Allow More Net expansion of the sandbox: adds (allow ...) rules, removes (deny ...) rules, or introduces a new process profile.
  • ◆ Combination Simultaneously tightens and relaxes permissions (e.g., blocking direct Mach service access in WebContent while allowing an alternative IOKit property or Narrower syscall).
  • ○ No Impact No runtime enforcement change (pure refactoring, comments, macro reorganization, build guards, or telemetry/logging modifiers).

Data Scope: Includes all git log --no-merges commits touching WebKit's iOS sandbox profiles across historical path moves (WebKit2/Resources/SandboxProfiles/ios → WebKit/Resources/SandboxProfiles/ios + WebKit/Shared/Sandbox/iOS).

3. Trigger Attribution & Binary Tags

  • OS / Framework / 3P Sandbox-only commits explicitly driven by iOS framework changes (UIKit, CoreText, Metal, AVFoundation, RunningBoard), dyld/libSystem, or 3P BrowserEngineKit rules.
  • Opaque Runtime Fix Sandbox-only permission expansions/fixes with terse rdar:// messages where OS framework vs. WebKit internal origin is not stated in the commit log.
  • WebKit Code-Coupled Commits that modify WebKit C++/ObjC/Swift source files alongside .sb profiles (e.g., moving APIs to GPU/Network process, state flags, new WebKit features).
  • Proactive Hardening Sandbox-only commits tightening attack surface (block-more) or reverting experimental blocks without C++ code changes.
  • apple-specific Rules gated on Apple code signing (apple-signed-executable?, process-attribute is-apple-signed-executable, signing-identifier "com.apple.WebKit...") or com.apple.private.* entitlements.
  • 3p-specific Rules gated on (require-not (process-attribute is-apple-signed-executable)), (log-streaming), or (require-not (logd-blocking)) for 3rd-party browser engines.
