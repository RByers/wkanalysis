1. 4-Stage Seatbelt-to-Code Analysis Methodology

  • Stage 1: Seatbelt Extraction Parse each service's .sb / .sb.in profile and diff its imports, Mach services, IOKit user-clients, filesystem paths, sandbox extensions, syscalls, and network rules against the core triad (WebContent, GPU, Networking).
  • Stage 2: Code & Entitlement Mapping Map every Seatbelt rule to exact C++/ObjC/Swift implementation files in Source/WebKit/, *.messages.in IPC receivers, and signing blocks in Scripts/process-entitlements.sh.
  • Stage 3: Git History & Lifecycle Trace every commit touching the service's sandbox profile and runtime directory from introduction to retirement or current HEAD state.
  • Stage 4: Synthesis & 3P Parity Evaluate why the capability was isolated from WebContent and whether third-party browser engines on iOS (BrowserEngineKit) can use or replicate it.

2. Uniqueness vs. Core Triad Taxonomy

  • Unique to Service Granted only to this auxiliary service/daemon; completely absent from WebContent, GPU, and Networking (e.g., com.apple.apsd, IOHIDLibUserClient, com.apple.frontboard.launchapplications).
  • Elevated vs. WebContent Blocked in untrusted WebContent but shared with GPU or Networking (e.g., outbound TLS networking, CARenderServer, SQLite sandbox extensions).
  • Shared Baseline Standard baseline OS rules inherited via common.sb (e.g., /usr/lib mapping, cfprefsd, sysctl reads).
  • Explicit Hardening Deny Capabilities explicitly blocked in the service profile (e.g., (deny network*), (deny dynamic-code-generation), (deny mach-bootstrap)).

3. 3rd-Party BrowserEngineKit Availability Tiers

  • Apple-Only (Private Daemon / Entitlement) Gated by com.apple.private.* entitlements or first-party system daemons (webpushd, adattributiond) unavailable to third-party engines.
  • Not in BrowserEngineKit Auxiliary process architecture or private framework (ModelProcess / CoreRE) with no BrowserEngineKit extension point.
  • OS-Brokered Public API Functionality now accessible to 3P browsers via public iOS APIs (ASAuthorizationController for Passkeys/WebAuthn).
  • Engine-Internal Capabilities a 3P engine implements inside its own BENetworkingProcess or host app container (e.g., IndexedDB/SQLite storage).
