1The attribution pipeline: from anchor click to appstored

When someone taps a web advertisement for a native iOS application, the advertiser and the ad network need to verify whether that click actually resulted in an app installation from the App Store. In Safari, Apple supports this through SKAdNetwork for Web Ads (and its successor framework, AdAttributionKit). The browser captures the ad click, binds cryptographic impression parameters, and transfers the attribution record directly to the operating system's App Store daemon (appstored), which later matches the record against the user's App Store purchase and dispatches a signed conversion postback.

In WebKit's source code, this entire pipeline operates through a dedicated fast path embedded within the DOM and networking engines:

  • Link detection in WebContent: When the user clicks an <a> element, HTMLAnchorElement::parsePrivateClickMeasurementForSKAdNetwork() inspects the link. If document().settings().sKAttributionEnabled() is true and the target URL begins with the prefix https://apps.apple.com/app/id, WebKit extracts the numerical catalog identifier (the Adam ID, Apple's internal catalog identifier for App Store items) via PrivateClickMeasurement::appStoreURLAdamID().
  • Impression metadata extraction: WebKit reads the attributionsourcenonce (an ephemeral cryptographic nonce identifying the impression) and attributiondestination attributes on the anchor, extracts the host page's registrable domain as the source site, and constructs a PrivateClickMeasurement object with m_adamID populated. The predicate pcm.isSKAdNetworkAttribution() evaluates to true whenever an Adam ID is present.
  • Forwarding to the Network process: When the navigation commits, WebPageProxy::didCommitLoadForFrame() in the UIProcess checks privateClickMeasurement->isSKAdNetworkAttribution() and forwards the attribution object to the website data store, which delivers it to the NetworkProcess over IPC.
  • Donation to appstored: In NetworkSession::storePrivateClickMeasurement(), WebKit checks if (unattributedPrivateClickMeasurement.isSKAdNetworkAttribution()) return donateToSKAdNetwork(...). Instead of writing the click to WebKit's local SQLite database for web-to-web Private Click Measurement, the Cocoa network session executes NetworkSessionCocoa::donateToSKAdNetwork(). This allocates an ASDInstallWebAttributionParamsConfig object, assigns the Adam ID, impression nonce, source domain, and destination ad network domain, and invokes the private system method [[ASDInstallWebAttributionService sharedInstance] addInstallWebAttributionParamsWithConfig:completionHandler:].

How Safari / WebKit does it

  • Detects App Store URLs (https://apps.apple.com/app/id...) decorated with attributionsourcenonce directly inside HTMLAnchorElement.
  • Wraps the click in a PrivateClickMeasurement stamped with the app's Adam ID.
  • Routes the click through NetworkSessionCocoa::donateToSKAdNetwork() directly to appstored via private AppStoreDaemon.framework SPIs.
  • The operating system manages attribution state, download validation, and cryptographic postback signing independently of whether the browser remains open.

What a BrowserEngineKit browser can do

  • Can detect App Store links in its own engine, but cannot communicate with appstored.
  • Opening the link launches the App Store via normal URL scheme handling, but the App Store receives zero attribution context.
  • No install attribution postback is ever generated for the ad network; app installations driven by web ads in third-party browsers remain entirely invisible to advertisers.

2The privilege barrier: com.apple.private.appstored and Mach sandbox gates

Even if an alternative browser engine implemented identical DOM parsing and constructed matching attribution payloads, it could not communicate with the App Store daemon. Access to appstored is guarded by two mandatory, kernel-enforced security boundaries: Apple-private code-signing entitlements and Seatbelt sandbox profiles.

How Safari / WebKit does it

  • Entitlement grant: In Source/WebKit/Scripts/process-entitlements.sh (lines 648–649), WebKit signs its iOS Network process with com.apple.private.appstored containing InstallWebAttribution. appstored verifies this entitlement via audit tokens on incoming XPC connections.
  • Seatbelt lookup grant: In Source/WebKit/Shared/Sandbox/iOS/networking-defines.sb (lines 144–146), WebKit's Networking sandbox explicitly allows Mach lookups for com.apple.appstored.xpc and com.apple.appstored.xpc.request.
  • Private SPI access: WebKit links against private AppStoreDaemon.framework classes (ASDInstallWebAttributionService, ASDInstallWebAttributionParamsConfig) cataloged under AllowedSPI-legacy.toml:112–113.

What a BrowserEngineKit browser can do

  • No entitlement: com.apple.private.appstored is an Apple-internal entitlement (classified as apple-private / ios-webkit-exclusive). Third-party apps and BENetworkingProcess extensions cannot receive it.
  • Sandbox denial: The public BrowserEngineKit networking extension profile does not permit Mach lookups for com.apple.appstored.xpc or com.apple.appstored.xpc.request; any connection attempt is blocked by the Seatbelt kernel sandbox.
  • AllowedSPI restriction: The ASDInstallWebAttribution* classes are flagged in the SPI inventory as apple-only-entitlement-or-daemon; third-party binaries referencing them fail App Store verification.

3Public framework limits: why AdAttributionKit and SKAdNetwork exclude web engines

Apple provides two public ad attribution frameworks for third-party developers: SKAdNetwork (StoreKit Ad Network, introduced in iOS 11.3) and AdAttributionKit (introduced in iOS 17.4 to support alternative app marketplaces alongside the App Store). However, both public frameworks are designed exclusively for native application contexts.

Apple's official documentation for SKAdNetwork for Web Ads explicitly documents this restriction:

Apple documentation statement: "SKAdNetwork for Web Ads is supported only in Safari. It isn't supported in WKWebView, SFSafariViewController, or any third-party browser." (Source: Apple Developer Documentation: SKAdNetwork for Web Ads).

Public AdAttributionKit APIs provide classes such as UIEventAttributionView, AdImpression, and AdAttributionKit.Postback. These APIs permit native iOS apps to register in-app ad impressions that lead either to app installations (app-to-app) or to merchant websites (app-to-web). Crucially, neither SKAdNetwork nor AdAttributionKit offers any public API for an application or browser engine to register a web-to-app impression from within a browser page.

BrowserEngineKit defines extension types for WebContent (BEWebContentProcess), rendering (BEProcessCapability), and networking (BENetworkingProcess). It provides no attribution capability or protocol (such as a hypothetical BEInstallWebAttribution). Consequently, if a user clicks an ad in Chrome, Firefox, or any third-party browser on iOS, the browser has no authorized mechanism to donate the click to the system install attribution engine. Because Apple's privacy guidelines strictly disallow probabilistic fingerprinting and alternative cross-app tracking without user consent, third-party browsers cannot provide any substitute measurement channel for advertisers.

How Safari / WebKit does it

  • Enjoys full OS-level integration through private AppStoreDaemon channels directly wired into the Safari app bundle and WebKit networking stack.
  • Ad networks receive cryptographically verified install postbacks from Apple's servers when Safari web ad clicks lead to App Store downloads.
  • Advertisers can confidently allocate ad spend to web campaigns in Safari because conversions are reliably measured.

What a BrowserEngineKit browser can do

  • No public API exists in StoreKit, AdAttributionKit, or BrowserEngineKit for web-to-app attribution.
  • Clicks leading to app downloads result in zero attributed conversions in SKAdNetwork or AdAttributionKit reports.
  • Ad networks and advertisers cannot verify ROI for ads served on third-party browsers, placing third-party browsers at a severe commercial disadvantage for web advertising.

Evidence

  • AppleSKAdNetwork for Web Ads — official documentation explicitly stating Safari exclusivity and excluding WKWebView and third-party browsers.
  • AppleAdAttributionKit framework — public framework documentation covering app-to-app and app-to-web conversions, but lacking web-to-app impression donation APIs.

4Architectural split: web-to-app install attribution vs. web-to-web PCM

To understand the WebKit implementation, it is vital to contrast web-to-app install attribution (analyzed here) with web-to-web Private Click Measurement (PCM) (analyzed in delayed PCM reports). While both share common DOM syntax and internal data structures, their execution paths and system dependencies diverge entirely.

On web pages, both features use the same HTML attribution attributes (such as attributionsrc, attributiondestination, and attributionsourcenonce), and WebKit parses both into instances of WebCore::PrivateClickMeasurement. However, inside NetworkSession::storePrivateClickMeasurement(), their paths branch based on the target URL:

  • Web-to-web PCM: When an ad on publisher.example links to merchant.example, isSKAdNetworkAttribution() is false. WebKit records the impression in its local PCM SQLite database. When the user later converts on the merchant's website, WebKit hands the matched attribution to adattributiond (the Private Click Measurement daemon; see services analyzer). adattributiond holds the report for a randomized delay of 24–48 hours to thwart timing-based user re-identification, then issues an HTTP POST request to the ad network's .well-known/private-click-measurement/report-attribution/ endpoint.
  • Web-to-app attribution: When the destination link points to the App Store (https://apps.apple.com/app/id...), isSKAdNetworkAttribution() is true. WebKit never records the click in the local PCM database and never interacts with adattributiond. Instead, it donates the click immediately and synchronously to appstored via ASDInstallWebAttributionService. appstored takes over full ownership: it monitors the App Store purchase pipeline, validates the download, cryptographically signs the attribution token, and sends the SKAdNetwork postback from Apple's servers.

While an alternative browser engine can implement web-to-web PCM independently using its own database and network stack, web-to-app attribution inherently requires cooperation from the operating system's application installer. Because only Apple's appstored manages iOS app installation, a browser cannot attribute app installs without an authorized bridge to that daemon.

5Evolution and history: SKAdNetwork 4.0 bridge, SPI migrations, and ephemeral sessions

WebKit's web-to-app attribution subsystem has evolved across several major iOS releases, reflecting continuous internal coordination between the WebKit engineering team and Apple's App Store daemon team:

  • March 2022 (iOS 16.0 / commit 4f69690a0415): WebKit introduced the "PCM to SKAdNetwork bridge". This commit added PrivateClickMeasurement::appStoreURLAdamID(), introduced AppStoreDaemonSPI.h, added the initial com.apple.private.appstored entitlement with capability InstallAttribution in process-entitlements.sh, and added the sandbox rule allowing Mach lookup of com.apple.appstored.xpc.request.
  • August 2022 (commit e485c1308288): The iOS Networking sandbox was expanded to also permit Mach lookups for com.apple.appstored.xpc, accommodating broadened communication with the App Store daemon.
  • May 2023 (iOS 17.0 / commit b40525e84793): WebKit replaced the older ASDInstallAttribution class with ASDInstallWebAttributionService, updating the entitlement string in process-entitlements.sh from InstallAttribution to InstallWebAttribution.
  • December 2024 (iOS 18.2+ / commit 5d5bb2812b45): WebKit adopted AdAttributionKit's private browsing verification protocol. For Private Browsing sessions, WebKit generates an ephemeral UUID session ID (m_donatedEphemeralImpressionSessionID) and assigns it to config.privateBrowsingSessionId. When the private session is closed, NetworkSessionCocoa::notifyAdAttributionKitOfSessionTermination() calls [ASDInstallWebAttributionService.sharedInstance removeInstallWebAttributionParamsFromPrivateBrowsingSessionID:completionHandler:], instructing appstored to purge any pending uninstalled attributions so private browsing actions cannot be linked after the session ends.
  • September 2025 (commit f3953af233f9): WebKit refactored iOS Seatbelt profiles, moving Mach lookup definitions into Source/WebKit/Shared/Sandbox/iOS/networking-defines.sb while maintaining the exclusive grants for appstored.

Across this four-year evolution, Apple repeatedly expanded and refined the private interface between WebKit and appstored, but at no point exposed a public BrowserEngineKit counterpart for competing engines.

Android comparison

On Android, web-to-app install attribution is fully open to all browser engines through two complementary mechanisms:

  • Play Install Referrer API: Any web browser on Android can link to an app listing in an app store using a URL containing a referrer parameter (for example, market://details?id=com.example.app&referrer=tracking_params). When the user installs the app, the app store client captures and stores the referrer parameters. Upon first launch, the installed application retrieves these parameters using the public Play Install Referrer Library. This mechanism works identically regardless of which browser displayed the ad link.
  • Android Privacy Sandbox — Attribution Reporting API: Android's modern, privacy-preserving Attribution Reporting API (part of Android AdServices) explicitly supports Web-to-App measurement. The system allows any browser engine (not just Chrome) to register web ad attribution sources via the Android AdServices measurement manager or standardized HTTP response headers. When the user installs and opens the app, the operating system's AdServices runtime matches the conversion and dispatches attribution reports directly. The capability is implemented at the OS level and exposed equally to all browsers through public Android Jetpack and system SDK APIs.
